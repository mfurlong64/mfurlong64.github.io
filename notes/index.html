Notes from building the platform

Twelve things I learned building construct-analyst, a BigQuery data platform, over a summer. Each one was paid for with a number that looked right and was not. They are written as rules because that is how they now live in the code: each has a test, a guard, or a build step that fails when it is broken.

01

The latest partition is not the widest one

Every source lands in a date-partitioned table, and the obvious way to read "the current state" is to take the newest partition. That was wrong three times, for three different reasons. The launch feed is incremental, so the newest partition held 42 of 983 launches. The App Store sweep runs narrow on weekdays and wide on Sundays, so the newest partition was usually the smallest one, 164 apps against 8,065. And a failed run can leave a partition that exists and is nearly empty.

The fix is a function that picks the widest recent snapshot by row count, and a rule that nothing else is allowed to choose a partition. It lives in the semantic layer, next to the other definitions, so there is one copy to get right.

Never read MAX(ingested_date). Ask which snapshot is complete, and let one function answer.
02

Uniqueness is not correctness

Two dimension tables in the star schema passed every grain check: one row per key, no duplicates, no nulls. They also reported 1,623 and 1,625 flown launches against a truth of 810. The keys were unique because they included the ingest date. The business key was not, and nothing checked that.

What was missing was a single rule for "one row per business key, latest ingest wins", applied before the dimension is built. It now exists once, and both dimensions use it. The grain checks stayed; a count-against-truth check was added beside them.

A grain check proves the key is unique. It does not prove the key is the right one.
03

The same definition existed three ways

The App Store's game subgenre is a small categorical, sixteen values. One board spelled the role-playing genre "Role-Playing", another "Roleplaying", and the table catalogue documented taking the localised label from the feed, which turns sixteen subgenres into 148. Three copies of one idea, each a little different, each written by someone who did not know about the others.

There is now one module that owns definitions like this, and a test that scans the codebase and fails if a fourth copy appears. The canonical labels are Apple's own US storefront strings, and the test was mutation-checked: I put a fourth copy in and watched it fail.

Definitions live in one file. A test guards the file, not the people.
04

Blank has several spellings

A public table of 86,545 Steam games ships four playtime columns that are zero for every row, two text columns that are the empty string for every row, and a tags column whose value is the literal two-character string "{}" for every row. A null check finds none of that. An average over the playtime columns returns a plausible number.

So the platform profiles a result set before anyone writes a conclusion on it: null and zero coverage, cardinality, quartiles, outliers, and a set of quality flags that treat all-zero and all-empty as critical. The profile runs from the CLI and in the app, and it runs before the analysis step, not after.

Profile a table before you believe it. Blank is spelled '', {}, [], 0 and NULL.
05

Record spend where the spending happens

Every query was supposed to be recorded in a cost ledger and a history log. The callers were responsible for that, and the callers were many. When I audited the ledger against BigQuery's own job list, it had seen 32 of 145 real jobs.

The recording moved inside the one function that runs a query. Callers cannot forget what they no longer do. The same day, the month-to-date figure on the health board became believable for the first time.

Instrument the choke point. Anything a caller must remember, a caller will forget.
06

The guard refuses; it does not warn

BigQuery will tell you, for free, how many bytes a query would scan. The platform runs that dry run before every real execution and compares it to a 100 MiB cap. Over the cap, it stops and prints the estimate, the cost at on-demand rates, and which tables it would have read. A flag raises the ceiling to 1 GiB for a deliberate large read; a monthly cap binds even then; a server-side daily quota binds even if all of that is wrong.

Warnings get scrolled past. Refusals get read. The whole platform, five feeds, a Sunday sweep of 391 requests, hundreds of analyses, has billed nothing.

Estimate first, refuse over the line, and keep a limit the code cannot reach.
07

A hand-typed number fails the build

A published board once said one thing in its prose and showed another in its chart. Both were from the same data; the prose had been typed from an earlier run. Nobody noticed for a while, because the prose read well.

Walkthrough boards now render every figure in the argument from a placeholder that is computed from the tile's own DataFrame at build time: a value, a share, a rank window, a comparison against the next five. If a literal number appears in a step, the build fails. Years are the one exception, and they have to be declared.

Derive the claim from the data it stands next to, or do not make the claim.
08

A test was holding the bug in place

The board summary summed gigabytes scanned across every tile, including tiles served from cache, which scan nothing. A board of one 0.287 GB query and two cached copies printed 0.86 GB scanned. The unit test asserted 0.18 GB for two cache hits, so the test agreed with the bug and would have failed a fix.

Fixing the code meant fixing the test, and then asking why the test had been written to a wrong expectation: it was written from the output, not from the definition. The definition now appears in the test's name.

When a fix breaks a test, ask whether the test was ever right.
09

Tests were not enough. Look at it

Ninety-three passing tests shipped four CSS bugs and a board whose own thesis contradicted its chart. Later, with more tests: a cadence rendered as "within its 1 day ago cadence", a table clipped so a whole column vanished, a series flattened onto a shared axis so 170 read as zero, and a currency label rendered as italic maths because matplotlib ate the dollar signs. Every one of those passed its unit tests. None survived being looked at.

So every published page is screenshotted in a real browser, at two widths and both themes, and the build fails on console errors or horizontal overflow. The 3D pages get more: a script opens each mode, freezes the clock, waits for real frames, measures the canvas, and clicks a shape to confirm the data card carries every column.

A test proves the code you thought to test. A screenshot shows what shipped.
10

Backfill is a property of the source

Three of the five feeds serve current state only. Apple's chart feed, the itch.io browse pages and the satellite catalogue have no archive; if a day is missed it is gone. And the raw layer had stored what the parser made of each response, never the response itself, so a parser bug could not be replayed either.

The forward half is fixable: raw response bodies are now archived, keyed by run and request, and a re-parse of an archived body reproduces its rows with no network call. The backward half is not fixable, and the docs say so, because the honest answer to "can we backfill" is a fact about the source, not about effort.

Keep the raw response. Know which sources have a past.
11

The renderer does no arithmetic

The boards can switch a tile into 3D: a fish per row, a spike per country on a globe, three numeric columns as a point cloud. All of that is JavaScript, and JavaScript in a browser is hard to test. So every height, coordinate, colour bucket and label is computed in Python, under pytest, and travels to the browser in a payload. The renderer only draws what it is given.

The other half of the contract: nothing is dropped quietly. Countries that could not be placed, draw caps, aggregations, the scale that was chosen, all travel in the same payload and print under the canvas where the reader can see them.

Put the arithmetic where the tests are. Print what the picture leaves out.
12

Prefer the API to the scan

The World Bank's indicators are mirrored in BigQuery, and reading fisheries for 199 countries from that mirror cost a 287 MB scan, because the mirror is not partitioned. The same indicators come from the World Bank's own HTTP API in one request per panel, for free, with the same numbers. Twenty-eight years of four panels plus a bilateral trade matrix for 5,821 country pairs took about thirty requests.

Two rules came out of the globes that followed. One scale across the whole time series, never one per year, or the growth the slider exists to show disappears. And a missing year is no-data grey, never zero.

Before scanning a warehouse mirror, ask whether the source will just tell you.
