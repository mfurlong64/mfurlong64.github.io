meta.ingest_runs

Most of the work in analysis is not writing the query

It is knowing whether the table is what it claims, whether the scan will cost anything, and whether the number you are about to quote is real. Each of those is a layer here, not a habit.

sources

Five public feeds, fetched on a schedule

Celestrak orbital elements, Launch Library, Apple App Store charts, itch.io, and reference dimensions. A launchd job runs them daily at 08:00.

l0_raw

Append-only, with the raw body kept

Every run lands as new rows and is recorded in a run table. Nothing is overwritten, so any figure traces back to the fetch that produced it.

l1_clean

Deduplicated views under contract

One row per business key, latest ingest wins. A separate dbt project holds 39 tests and 8 freshness checks over these views and nothing else.

l2_marts

A star schema, built by one module

Dimensions and facts with grain checks. Uniqueness is not correctness, so the semantic layer defines each measure once and the tests fail if a second copy appears.

boards

One self-contained HTML page

Inline SVG charts, optional 3D modes, a trust score per tile, and the SQL under a disclosure. No server, no CDN. Hand the file to anyone.

Notes from building it

Short, specific lessons, each one paid for with a number that looked right and was not. All twelve are here.

01

The latest partition is not the widest one

MAX(ingested_date) was wrong three times, for three different reasons.

 02

Uniqueness is not correctness

Two dimensions passed every grain check while reporting twice the flown launches that existed.

 07

A hand-typed number fails the build

After a board's thesis contradicted its own chart, every figure in a walkthrough is derived from the tile beside it.
